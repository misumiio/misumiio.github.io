随笔：手搓代码与这个时代

发表于 2026-09-20

近期翻了一下自己的blog, 看到好几年前的手搓代码做的有意思的东西（例 https://misumiio.github.io/2023/06/06/%E8%AE%A1%E7%AE%97%E5%B0%BA%E7%9A%84%E5%8E%9F%E7%90%86%E4%B8%8E%E5%88%B6%E4%BD%9C/ ）并且回忆起当时快乐的手搓代码时光，感叹那样的时光不会再来了啊。不禁开始臆想如果我出生的时间，对应的时代是互联网的黄金时代，而非AI的黄金时代，会是怎样的一个场景呢？我读了随便一个什么大学，并不一定是名校，由兴趣进入计算机专业，上班就手搓代码，看看机器的运行状况，并没有什么复杂的东西，不一定要沾什么艰难的算法，就干个大专计算机也能干的活，赚了钱就回家休息，也不用考虑商业逻辑与人际关系，也没有网络小鬼跳脸，那是何等纯真自然而理想的生活方式啊，如同“风乎舞雩，浴乎沂，咏而归”一样。

相比纯正的技术宅，我写的东西并没有那么多，但是还是由兴趣写了一些。我最后一次在课程外手搓代码，最晚可以追溯到2025-02, 那时候我为linux开发了一个PDF双面打印与小册子打印的工具。（注：此时已经使用AI写UI了）遇到好像是pdf拼接的问题没法解决，上网抄代码，最后是在不知道什么地方找到了一个日本人写的代码，解决了这个问题。那时候还很有意思的是，好像还得把用的库锁版本，如果更新了就没法用了，说是有个函数弃用了，有新的写法，但是新的写法也没法复现原来的效果，感觉好像是新的库出bug了。

处于古法与现代写代码之间的，是AI时代与AI Agent时代之间。一年前的程设H，开发东西的搭档用gemini跑了好多东西（我没有谷歌账号，我跑不了），那时候就是在对话中复制代码，粘贴运行，复制报错信息并让AI修改；AI还可能把已经有的东西改坏掉……那时候他跑不通，然后我们就在青年之家，我用着他的电脑，调调改改给他搞通了跑起来了。感觉自己像一个老师傅，可能学习不过人家，编代码也竞争不过别人，但是遇到乱七八糟的问题我更有可能解决。现在想来那可能是我最后的价值体现，再后来就出现了Agent。

刚想写下自己这样的想法并不是拒绝AI带来的变化，因为我也享受到了AI带来的便利，真实地用AI开发了东西。随即发现不是的，我确实就是在惧怕AI的影响、在人的价值被AI替代之际迷茫，这样来说，可能我也可以算得最后一批前Ai时代的老东西了吧。现在来说，就算对什么东西有些兴趣，也只会让AI代工，不太可能愿意自己手搓代码了。开发些什么东西将来或许会成为我的工作，也或许不会。当手搓代码的乐趣处于被转化为工作和被更方便的东西替代这两者的两面夹击中，乐趣可能就不复存在了。

意义之塔上有什么？我有时练琴，那是为了什么；顶着补四个物理课，转向计算机专业，学着一个正在滑落的专业的基础课程，是为了什么？（学那些数理基础既没有什么重大的意义，也不是我本身想学的，因此不在讨论之列。）人不能总是只考虑前途、赚钱和机会成本，经济学上的概念不能取代意义。一方面，由于人的寿命有限，所以对自身未来的投资的收益是有尽头的。另一方面，在什么东西都可能被取代的时候，意义本身需要一个答案。

Linux刻光盘：xorriso图形界面开发

发表于 2026-07-12 更新于 2026-08-06

编写项目的背景

众所周知，Linux 系统一直缺乏一个好用的刻录光盘的软件。Brasero 软件的功能比较简单，而 k3b 是比较好用的软件，但是他采用的后端既不支持使用 UDF 的蓝光光盘续刻，也不支持使用iso9660的蓝光光盘进行续刻。也就是说在Linux系统下, 无法对蓝光光盘进行续刻 (Muliti-sessioning)。也就是说蓝光光盘必须一次性先准备好所有的文件进行刻录，之后没办法再追加了。这是对光盘存储空间的极大浪费。

k3b 软件并没有明确标明不支持蓝光光盘的续刻，而是在实际上刻录完第一次之后想要续刻的时候，提示介质不支持续刻了（具体的提示我已经忘记）。这样的一个问题曾经困扰我很久，之后我在互联网上找到一篇英文的帖子 https://forums.linuxmint.com/viewtopic.php?t=428014 ，讨论了这个问题。下面的人提出：k3b使用的后端均不支持蓝光光盘的UDF续刻，然而好在iso9660实际上并没有2GB的文件大小限制，所以我们可以仍旧使用iso9660。xorriso软件默认就打开最大级别的iso9660文件大小限制，所以我们可以用xorriso来刻录多分段的光盘。例如这篇帖子中回答者提供的示例代码：

# To address your DVD or Blu-ray dive as target device do:
iso=/dev/sr1
# But before using slow optical media, try with an image file on fast disk.
# (Make sure this file does not exist yet.)
iso=/...some.large.filesystem.../test.iso

# Choose some large test files
file1=/.../some_large_file
file2=/.../some_other_large_file

# Write first session
xorriso -outdev "$iso" -map "$file1" /file1

# Write second session
xorriso -dev "$iso" -map "$file2" /file2

# Mount on a GNU/Linux system
mount_point=/mnt/iso
sudo mount "$iso" "$mount_point"
ls -l "$mount_point"

这个工具只有命令行程序。虽然有对话模式可以在里面进行编辑，但是这些命令并不是和外面的bash完全兼容的，敲起来也不太习惯，学习成本比较高。因此我为这个工具开发了一个图形界面。

界面的主要操作逻辑就是左边是硬盘的文件系统，右边是光盘的文件系统。左右拖拽可以进行提取、刻录等计划，点击执行会最终执行。

项目地址：https://github.com/misumiio/xorriso-gui

KDEplasma面板崩溃

发表于 2025-02-01 更新于 2025-02-11

KDE Plasma面板经常崩溃，然而killall plasmashell不管用。网上没有找到解决办法。

经实测，发现killall -9 plasmashell就行了。

这就类似windows explorer重启。

还有其他意想不到的效果：

本来KDE wayland和x11的鼠标指针大小不是同一个标准，如果电脑屏幕有150%缩放，则wayland的24号鼠标指针等于x11的36号。在x11里面修改鼠标指针大小只会对新打开的应用生效，然而桌面不会，很难受。现在我们知道了，包括桌面和panel全部都是plasmashell这个进程，我们把他杀掉他就会自动重启，鼠标指针大小正常了。

抽牌算二十四点有解的概率问题

发表于 2025-01-28

闲着没事的阿玮提出了这么个问题：在一副扑克牌中任抽4张，算24点，有解的概率是多少。

（注：不允许使用乘方、开根、求导、阶乘等计算。）

于是开始研究：

  1. 计算任意一组数一个的二十四点表达式的算法解决：

上bing搜索，copilot太热情了，直接给出了算法。这个算法的原理就是枚举四个数之间所有可能的数学四则运算表达式，然后一个个算。测试代码发现可用。既然可以使用，那么具体原理不深究了。代码如下(cal24.py)：

from itertools import permutations, product

def calculate(a, b, op):
    if op == '+':
        return a + b
    elif op == '-':
        return a - b
    elif op == '*':
        return a * b
    elif op == '/':
        if b != 0:
            return a / b
        else:
            return None

def solve_24(nums):
    operators = ['+', '-', '*', '/']
    for num_perm in permutations(nums):
        for ops in product(operators, repeat=3):
            # Try different parenthesis combinations
            expressions = [
                f"(({num_perm[0]} {ops[0]} {num_perm[1]}) {ops[1]} {num_perm[2]}) {ops[2]} {num_perm[3]}",
                f"({num_perm[0]} {ops[0]} ({num_perm[1]} {ops[1]} {num_perm[2]})) {ops[2]} {num_perm[3]}",
                f"{num_perm[0]} {ops[0]} (({num_perm[1]} {ops[1]} {num_perm[2]}) {ops[2]} {num_perm[3]})",
                f"{num_perm[0]} {ops[0]} ({num_perm[1]} {ops[1]} ({num_perm[2]} {ops[2]} {num_perm[3]}))",
                f"(({num_perm[0]} {ops[0]} {num_perm[1]}) {ops[1]} ({num_perm[2]} {ops[2]} {num_perm[3]}))"
            ]
            for expr in expressions:
                try:
                    if abs(eval(expr) - 24) < 1e-6:
                        return expr
                except ZeroDivisionError:
                    continue
    return 0

# 示例使用
nums = [8, 12, 6, 6]
solution = solve_24(nums)
print(solution)
  1. 一副52张的扑克里面抽牌，抽到一个特定组合的概率是多少：

分析这个问题可以发现，所有的组合可以分类如下：

AAAA型, AAAB型, AABB型, AABC型, ABCD型。

没有其他可能的分布。

计算这5种组合中，特定一种组合出现的概率。

总抽法是comb(52, 4)。(注：comb是qalculate写法，表示组合数; perm是qalculate写法, 表示permutation, 排列数)

AAAA型：1 / comb(52, 4)

AAAB型：考虑花色。A牌是在四个花色中选了3个，B牌是在四个花色里面选了一个。全部考虑顺序。则概率为4/52 * 3/51 * 2/50 * 4/49 * perm(4, 4)。

AABB型：同理。4/52 * 3/51 * 4/50 * 3/49 * perm(4, 4)

AABC型：同理。4/52 * 3/51 * 4/50 * 4/49 * perm(4, 4)

ABCD型：同理。4/52 * 4/51 * 4/50 * 4/49 * perm(4, 4)

具体的数据见代码。

把所有情况列出，所有概率加和，发现略小于1。正常现象，因为python浮点数存在误差。

代码如下（stat.py）:

import cal24
pa = 0
for f in range(1, 14):
    for i in range(1, f+1):
        for j in range(1, i+1):
            for k in range(1, j+1):
                if f != i and i != j and j != k:
                    # case1: abcd
                    # p = 2816/4165
                    p = 24*32/812175
                elif f == i and i != j and j != k or f != i and i == j and j != k or f != i and i != j and j == k:
                    # case2: aabc
                    # p = 2112/20825
                    p = 12*8/270725
                elif f == i and i == j and j != k or f != i and i == j and j == k or f == i and i != j and j == k:
                    # case3: aaab
                    # p = 96/20825
                    p = 4*4/270725
                elif f == i and i != j and j == k:
                    # case4: aabb
                    # p = 216/20825
                    p = 6*6/270725
                elif f == i and i == j and j == k:
                    # case5: aaaa
                    # p = 1/20825
                    p = 1/270725
                expr = cal24.solve_24([f, i, j, k])
                print(f, i, j, k, expr)
                if expr:
                    pa += p


print(pa)

房里被装了监控，有一两年了，一直想想办法干扰，现在做了一个完美的解决方案，供参考。

本来希望通过DNS来阻断，但是DNS有缓存之类的东西，而且猾伪路由器篡改我的DNS，而且我在Adguard Home里面也没有找到有关小米API的DNS解析记录，所以放弃。没想到最后采用的方案效果比之前还要好。

买一个树莓派全天候运行，装好firefox, geckodriver, python的selenium, 使用screen -S ban -s ban后台运行ban脚本，把脚本放在PATH下面。

原理是自动模拟人登录路由器后台手动禁止联网，过一段时间模拟人手动允许他联网。
我一开始绝对不会想到这么离谱的想法最后会采用而且效果这么好。

踩到的坑稍微做一下总结：

service对象不能再driver对象退出以后重复使用，也就是service = S……这句不能写在while True外面。否则报错。很奇怪的坑，网上没有解决方案，最后是我自己改对的。

对于要点击的对象一定要wait.until等他加载出来。

路由器里面设备的序号是会变的，正如我注释掉的代码，所以最好的方式使用MAC地址来定位。通过XPATH寻找与定位MAC文本同框的按钮，非常稳定。

driver如果每次都新实例化比较慢和占CPU, 如果每次只用同一个driver会内存泄漏，所以折中，每64次ban，关掉浏览器重新实例化一个driver.

总结

每隔几十秒断网十几秒，实测监控不会显示断线，APP上面只能看到卡顿转圈圈，卡很久能进去，看了十几秒画面又不动了。

使用flask和简单的html写了一个简单的信息课聊天室

from flask import Flask, request

app = Flask(__name__)

msglist = []

@app.route("/", methods=["POST", "GET"])
def root():
    global msglist
    if request.method == "GET":
        ip = request.remote_addr
        reqnum = ip[ip.rfind(".")+1:]
        user = request.values.get("user")
        message = request.values.get("message")
        print(reqnum, user, message)
        if (user and message) and (not msglist or msglist[0] != (reqnum, user, message)):
            msglist.insert(0, (reqnum, user, message))
    

    with open("chat.html", 'r') as f:
        text = ""
        name = ""
        for fornum, user, message in msglist:
            text += "<p>%s,%s: %s</p>" % (fornum, user, message)
            if not name and reqnum == fornum:
                name = user
        # 防止老师直接偷看
        if ip == "10.10.50.49":
            return ""
        return f.read() % (name, text)

app.run(host="0.0.0.0", port=8080, debug=False)
